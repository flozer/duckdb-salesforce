# duckdb-salesforce v0.22.1

> **Auth fix for public connected apps + base64 decoder hardening.** Patch
> release. Supported DuckDB set unchanged: **{v1.5.6, v2.0.0, v2.0.1}**. No
> new function, setting, or write capability (28 functions, unchanged).

## What changed

- **Fix: refresh-token exchange with an empty `client_secret`**
  ([#95](https://github.com/flozer/duckdb-salesforce/issues/95), fixed by
  [PR #96](https://github.com/flozer/duckdb-salesforce/pull/96) from
  @connordouglashanna - thank you!). SFDX auth URLs generated by the
  Salesforce CLI use its public connected app and carry an empty secret
  (`force://PlatformCLI::<refresh_token>@<host>`). The token request sent an
  empty `client_secret=` parameter, which Salesforce rejects with
  `invalid_client`, so `ATTACH ... (auth_source 'sfdx_url')` failed. The
  parameter is now omitted when the secret is empty, which Salesforce accepts.
  The usage guides now capture the URL with `sf org auth show-sfdx-auth-url`.
- **`client_secret` is now optional on every refresh-token path.** Public
  connected apps have no secret, so requiring one blocked them outside
  `sfdx_url`:
  - `ATTACH` with `auth_source 'options'` (the `client_secret` option);
  - `ATTACH` with `auth_source 'env'` (`SF_CLIENT_SECRET`);
  - `salesforce_query(...)` and `salesforce_describe(...)` (`client_secret :=`).

  `client_id` and `refresh_token` remain required. A confidential connected
  app still needs its secret; omitting it yields Salesforce's
  `invalid_client` error with the existing secret-free hint.
- **Fix: signed-integer overflow in the base64 decoder** used for BLOB
  fields. The bit accumulator is masked to 24 bits; it previously overflowed a
  signed `int` (undefined behavior) after a few characters. Decoded output is
  unchanged (verified against a reference decoder over 370 cases).
- **Internal cleanup:** removed the `SF_DUCKDB_HAS_IDENTIFIER` compile flag and
  its `#if` branch. It only existed for v1.5.4/v1.5.5 (dropped in v0.21.0);
  `duckdb::Identifier` exists on every supported ref.
- **Tests:** new offline cases in `salesforce_auth_source.test` cover the empty
  SFDX secret (from PR #96) and the four secret-less paths above. The mock
  rejects an empty `client_secret=` like live Salesforce, so these tests fail
  if the parameter is sent empty.

## Packaging notes

- Release assets are built against **DuckDB v1.5.6**, unchanged.
- DuckDB v2.0.0 / v2.0.1 users build from source against their ref, or install
  from the DuckDB community registry after the separate maintainer-approved
  descriptor update.
- Published v0.22.0 and earlier tags and releases remain untouched.

## Why v0.22.1 (patch)

Bug fixes plus a backward-compatible relaxation (an option that was required
becomes optional). No supported-version change, no removed behavior.
