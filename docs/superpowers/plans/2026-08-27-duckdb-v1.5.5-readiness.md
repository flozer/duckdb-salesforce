# DuckDB v1.5.5 Compatibility + v2.0 Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generalize the local DuckDB build matrix script, validate the extension against DuckDB v1.5.5 (Release+Debug, full offline suite), run a non-blocking canary against `duckdb/main` to scope v2.0 API drift, and update operational/compat documentation — with zero live tests, zero release/tag/community actions, and zero remote CI runs.

**Architecture:** `scripts/build_matrix.ps1` becomes portable (no hardcoded personal paths/pins), submodule-safe (always restores original HEAD via `finally`), and env/parameter driven. It builds each requested ref in an isolated build directory, runs the offline `.test` suite, and reports SHA/compiler/results. Code changes to `src/` happen only where the v1.5.5 build or offline suite actually fails — this repo already builds clean against v1.5.2-v1.5.4, so no changes are assumed in advance. The v2.0 canary is read-only intelligence gathering: it never mutates `src/`, only produces a categorized error inventory and a separate C Extension API capability-matrix doc.

**Tech Stack:** PowerShell 7 (`pwsh`), CMake + Ninja + MSVC (`cl`) via `vcvars64.bat`, vcpkg (`x64-windows-static` triplet), DuckDB extension build system (`extension-ci-tools` Makefile), DuckDB `.test` sqllogic suite, git submodules.

**Spec:** This plan implements the PM work order delivered 2026-08-27 (Entregas 1-5, verbatim in Portuguese) — reproduced in full in "Appendix: Original PM Order" at the end of this document. Executors should read both.

- [ ] **Step 2: Rewrite parameter block and env-var driven tool discovery**

Replace the hardcoded path block with parameters + env-var fallbacks + `Get-Command` discovery. Target shape:

```powershell
[CmdletBinding()]
param(
    [string[]]$Tags = @('v1.5.4', 'v1.5.5'),
    [string]$Baseline = 'v1.5.4',
    [string[]]$CanaryRefs = @(),
    [ValidateSet('Release', 'Debug', 'Both')]
    [string]$Configuration = 'Release',
    [string]$Root = (Resolve-Path "$PSScriptRoot\.."),
    [string]$VcVars = $env:DUCKDB_SF_VCVARS,
    [string]$CMakePath = $env:DUCKDB_SF_CMAKE,
    [string]$NinjaPath = $env:DUCKDB_SF_NINJA,
    [string]$VcpkgToolchain = $env:DUCKDB_SF_VCPKG_TOOLCHAIN
)

function Resolve-Tool {
    param([string]$EnvValue, [string]$CommandName, [string]$FriendlyName)
    if ($EnvValue -and (Test-Path $EnvValue)) { return $EnvValue }
    $found = Get-Command $CommandName -ErrorAction SilentlyContinue
    if ($found) { return $found.Source }
    throw "Cannot locate $FriendlyName. Set `$env:DUCKDB_SF_$($FriendlyName.ToUpper()) or ensure '$CommandName' is on PATH."
}

$vcvars = Resolve-Tool -EnvValue $VcVars -CommandName 'vcvars64.bat' -FriendlyName 'VCVARS'
$cmake = Resolve-Tool -EnvValue $CMakePath -CommandName 'cmake.exe' -FriendlyName 'CMAKE'
$ninja = Resolve-Tool -EnvValue $NinjaPath -CommandName 'ninja.exe' -FriendlyName 'NINJA'
if (-not $VcpkgToolchain) {
    if ($env:VCPKG_ROOT) { $VcpkgToolchain = Join-Path $env:VCPKG_ROOT 'scripts/buildsystems/vcpkg.cmake' }
    else { throw "Set `$env:DUCKDB_SF_VCPKG_TOOLCHAIN or `$env:VCPKG_ROOT." }
}
```

No personal usernames or drive-letter-specific paths remain in the file. `$Root` defaults to the script's own parent's parent (portable across clones).

- [ ] **Step 3: Submodule HEAD discovery + guaranteed restore**

Discover the original HEAD before any mutation, and wrap the whole per-ref loop in `try/finally`:

```powershell
Push-Location (Join-Path $Root 'duckdb')
try {
    $originalHead = (git rev-parse HEAD).Trim()
} finally {
    Pop-Location
}

$results = @()
try {
    foreach ($ref in $refsToTest) {
        $results += Invoke-MatrixBuild -Ref $ref -Root $Root -Configuration $Configuration `
            -CMakePath $cmake -NinjaPath $ninja -VcVars $vcvars -VcpkgToolchain $VcpkgToolchain
    }
}
finally {
    Push-Location (Join-Path $Root 'duckdb')
    try {
        git checkout -q $originalHead
        $restoredHead = (git rev-parse HEAD).Trim()
        if ($restoredHead -ne $originalHead) {
            Write-Error "Submodule restore FAILED: expected $originalHead, got $restoredHead"
            exit 1
        }
        Write-Host "Submodule restored to original HEAD: $originalHead"
    } finally {
        Pop-Location
    }
}
```

This satisfies "descobrir e restaurar automaticamente o HEAD original" and "não deixar o submódulo em estado incorreto após sucesso ou erro" literally — restore happens in `finally` and is itself verified.

- [ ] **Step 4: Accept tag, branch, or SHA; record the SHA actually tested**

`$ref` can be any of the three. Resolution must not assume a tag:

```powershell
function Resolve-Ref {
    param([string]$Ref)
    Push-Location (Join-Path $Root 'duckdb')
    try {
        git fetch --depth 1 origin $Ref 2>$null | Out-Null
        $sha = (git rev-parse "$Ref^{commit}" 2>$null).Trim()
        if (-not $sha) { throw "Cannot resolve ref '$Ref' to a commit (not a tag, branch, or SHA known to the submodule)." }
        return $sha
    } finally {
        Pop-Location
    }
}
```
